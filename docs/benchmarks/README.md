# Benchmarks

Machine: Intel i7-13620H (16 threads), 16 GB RAM, Fedora 44, GNOME 50 Wayland, CPU only,
platform profile `quiet` / governor `powersave`. Generated by `npm run test:integration`
(`ECHONOTE_TEST_LLM=qwen2.5-0.5b-instruct-q4_k_m` for the 0.5B run). Speech inputs are espeak-ng
synthetic voices (`scripts/make-test-audio.sh`), which are harder to recognise than a human voice.
The first LLM request in each run includes building the prompt cache (the app does this at startup).

In-app end-to-end timings (from `captures.timings`, 1.5B model, warm):

| capture | audio | toggle → mic live | stop → audio saved | transcription | LLM | stop → organized |
| --- | --- | --- | --- | --- | --- | --- |
| reference | 5.1 s | 581 ms | 145 ms | 2104 ms | 5859 ms | 8146 ms |
| reminder | 4.6 s | 569 ms | 146 ms | 2201 ms | 4882 ms | 7370 ms |
| reminder | 5.1 s | 570 ms | 141 ms | 2237 ms | 5820 ms | 8307 ms |
| idea (offline netns) | 5.6 s | 151 ms | 146 ms | 2105 ms | 5403 ms | 7692 ms |

GNOME shortcut command → app receives toggle (named pipe): 27, 21, 17 ms. Cold (app not running): 1410 ms.

Memory (RSS, AppImage): after startup llama-server 1907 MB, whisper-server 105 MB, Electron (9 processes,
shared pages counted repeatedly) 737 MB; after 5 captures 1908 / 164 / 957 MB. With `-c 2048 -ub 256`
llama-server measured 1817 MB standalone.
